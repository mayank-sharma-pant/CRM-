# SSO (Google / Microsoft) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Existing users can sign in with Google or Microsoft OAuth; cookies/MFA match password login.

**Architecture:** `oauth_identities` table; `app/services/auth/oauth.py` builds auth URLs, exchanges codes (httpx), resolves users; router under `/api/auth/oauth`; login page buttons + query handling.

**Tech Stack:** FastAPI, httpx, SQLAlchemy, Next.js. pytest + TestClient + httpx mock.

**Spec:** [docs/superpowers/specs/2026-08-25-phase4-sso-design.md](../specs/2026-08-25-phase4-sso-design.md)

## Global Constraints

- No new pip deps. No Alembic. New table via model + create_all.
- Login only — no SSO signup. Empty OAuth secrets ⇒ provider off.
- Test password `"pw"`. Reset `auth_limiter` when needed.
- pytest from `backend/` with `.venv/bin/pytest`.
